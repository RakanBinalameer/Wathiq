# وثّق — Wathiq

نموذج أولي (Hackathon) يحوّل **إملاء الممرض الصوتي** (عربي/إنجليزي ممزوج) إلى ملاحظة منظَّمة:
أدوية + جرعة/طريقة/تكرار، تشخيصات (ICD-10)، وعلامات حيوية، مطابَقة مع قاعدة معرفة طبية،
ثم **يراجعها الممرض ويؤكدها** قبل الحفظ.

**نسخة تجريبية منشورة:** https://wathiq.pythonanywhere.com — بيانات وهمية فقط، ولا تُدخل فيها بيانات مرضى حقيقيين. دقة التحليل على كلام ممرضين حقيقيين لم تُقَس بعد.

## تشغيل سريع
```bash
pip install -r requirements.txt
python wsgi.py            # أول تشغيل ينشئ القاعدة ويطبع كلمة مرور المستخدم nurse1 مرة واحدة
# http://127.0.0.1:5000
python -m pytest -q       # 47 اختباراً
```
بدائل: `DEMO_PASSWORD=... python scripts/seed_kb.py` لإعادة بناء القاعدة، أو `docker build -t nursevoice . && docker run -p 8000:8000 -e SECRET_KEY=... nursevoice`.
في الواجهة أزرار «جرّب مثالاً» تعمل بدون ميكروفون (عربي، إنجليزي، مختلط مع حساسية، جرعة زائدة).

## شرح مبسّط لغير المتخصصين
1. الممرض يتكلم أو يكتب ملاحظته.
2. النظام يوحّد الكتابة («أ/ا»، «ة/ه»، الأرقام ١٢٣) ويبحث عن كل اسم في **قاعدة معرفة ثابتة**. «بنادول» و«باراسيتامول» و«acetaminophen» = الدواء نفسه.
3. يلتقط الجرعة والطريقة والتكرار والعلامات الحيوية.
4. ينبّه: جرعة أعلى من المعتاد، حساسية المريض، اسمان متشابهان، قيمة مستحيلة.
5. كل ما ليس مؤكداً 100% يُوسَم «يحتاج مراجعة» ولا تُحفظ الملاحظة إلا بعد تأكيد الممرض. النظام **يبحث** في القاعدة ولا **يولّد** أدوية من عنده.

## البنية
| المسار | الوظيفة |
|---|---|
| `app/textnorm.py` | تطبيع العربية/الإنجليزية (يحافظ على مواضع الأحرف للتظليل) |
| `app/extract.py` | المطابقة (دقيقة أولاً ثم تقريبية)، الجرعات، العلامات الحيوية، فحوص السلامة |
| `app/seed.py` + `scripts/seed_kb.py` | بناء قاعدة المعرفة: عيّنة منسَّقة + Synthea + استيراد SFDA اختياري |
| `app/views.py` | الصفحات وواجهات API (الخادم يعيد التحقق من كل ما يُحفظ) |
| `app/stt.py` | تفريغ صوتي اختياري على الخادم (faster-whisper) |
| `training/gen_corpus.py` | توليد جمل إملاء اصطناعية (نص تسجيل + بيانات ضبط LLM) |
| `training/finetune_whisper.py` | وصفة ضبط Whisper (غير منفَّذة هنا) |
| `tests/` | اختبارات الاستخراج والأمان والحفظ والتغذية |

## ما أُنجز فعلاً وما لم يُنجز (بصراحة)
**منفَّذ ومُختبَر**
- قاعدة المعرفة: 266 دواءً و257 تشخيصاً؛ من Synthea: 461 منتج RxNorm (بعد استبعاد 56 غير قابل للتحليل مثل عبوات موانع الحمل) و204 تشخيصات SNOMED. `data/synthea_codes.json` مستخرج من وحدات Synthea (Apache-2.0).
- 53 تشخيصاً منسَّقاً يدوياً بأكواد ICD-10 (WHO) ومرادفات عربية. من أكواد SNOMED المرفقة **26 فقط تحقّقتُ منها مقابل Synthea**؛ البقية معلَّمة `snomed_verified=0`.
- الاستخراج، التنبيهات، بوابة التأكيد، الحفظ مع إعادة التحقق من الخادم، عرض الملاحظات حسب ملف المريض لجميع الممرضين (كل فتح لملاحظة كاتب آخر أو لملف مريض يُسجَّل في سجل المراجعة؛ لا يوجد بعد تقييد حسب الجناح أو فريق الرعاية). زمن التحليل ≈ 2 مللي ثانية.
- الأمان: CSRF، CSP صارمة بلا inline، ترويسات حماية، جلسة 30 دقيقة، تجزئة كلمات المرور، تحديد معدل الطلبات، لا يُسجَّل نص الملاحظة في سجل التدقيق، إخراج Jinja/DOM مُهرَّب.

**غير منفَّذ / يحتاج عملاً قبل أي استخدام سريري**
- **قائمة SFDA الرسمية لم تُدمج**: لا وصول للشبكة من بيئة البناء. الأدوية «المنسَّقة» عيّنة شائعة بأسماء تجارية معروفة وليست تحقّقاً من تسجيل SFDA (`sfda_verified=0` للجميع). لاستيراد الملف الرسمي: `python scripts/seed_kb.py --sfda-csv FILE.csv` (أسماء الأعمدة `generic_name,trade_name` قابلة للتعديل في `import_sfda_csv`؛ اختُبر على ملف تجريبي فقط).
- **ضبط Whisper/LLM لم يُجرَ**: يحتاج GPU وتسجيلات حقيقية من ممرضين بلهجات متعددة. المتوفر: مولّد جمل التسجيل، وسكربت الضبط (تحقّقتُ من صحة صياغته فقط)، ودعم تشغيل النموذج المضبوط عبر `WHISPER_MODEL`. الاستخراج الحالي قواعد + مطابقة تقريبية، وليس نموذجاً لغوياً.
- نسبة 100% في `gen_corpus.py` **دائرية** (الجمل مولَّدة من القاعدة نفسها) فهي اختبار انحدار وليست دقة حقيقية. مطلوب تقييم على تسجيلات حقيقية بمقياس WER ودقة أسماء الأدوية.
- الإملاء في الواجهة بدون Whisper يستخدم Web Speech API في Chrome (صوت يُرسَل لخدمة المتصفح). **لا يُستخدم مع بيانات مرضى حقيقية**. مساره لم يُختبر بصوت حقيقي في بيئة البناء.
- حدود الجرعات القصوى (`max_single_dose_mg`) وعتبات العلامات الحيوية مؤقتة ويجب أن يعتمدها الفريق الصيدلي/الطبي. تشخيصات Synthea الإضافية بلا ICD-10 (تُوسَم بذلك) ويحدّدها الترميز الطبي.
- لا تكامل مع نظام معلومات المستشفى (HIS/EMR) أو نظام دفع؛ غير مطلوبين في المواصفات المقدَّمة. يوجد **تصدير** بصيغة HL7 FHIR R4 لكل ملاحظة محفوظة (`GET /api/notes/<id>/fhir`: `MedicationStatement` و`Condition` و`Observation`)، وهو ملف جاهز للتبادل وليس ربطاً حياً مع أي نظام. تحقّقتُ من بنيته بنماذج `fhir.resources` (R4B) فقط، ولم يُفحص بمدقّق FHIR الرسمي ولا مقابل أي خادم أو دليل تنفيذ سعودي.
- للإنتاج: HTTPS (`FORCE_HTTPS=1`)، `SECRET_KEY` ثابت، قاعدة بيانات مُدارة بدل SQLite، مخزن تحديد معدل مشترك (Redis)، تشفير البيانات الساكنة، وموافقة الأمن السيبراني وحماية البيانات (PDPL / NCA).
